# 博客写作经验与规范

- 整理日期：2026-10-20
- 来源：《AI、模型、Agent、Harness》一文从初稿到定稿的全部有效修改意见（含两轮外部审查与本会话的多轮迭代）。
- 用法：写新文章时，动笔前读第一、二节；发布前用第三至五节过一遍；修订与外审按第六、七节的流程。
- 逐条意见的来龙去脉见 [`docs/reviews/ai-model-agent-harness-revision-log.md`](./reviews/ai-model-agent-harness-revision-log.md)，本文只保留可复用的结论。

## 一、写作流程

1. **先大纲后动笔**：大纲 = 章节结构 + 每节要点 + 配图清单（张数、插入位置、画什么），先给作者确认再写正文。
2. **图文同审**：初稿和配图一起送审；改正文后必须同步过一遍图注 / alt / 对照表 / 大事记 / metadata summary。
3. **批注式修订**：作者在本地编辑器里给句子加【】标注（【改成：xxx】【删掉这段】【举例换成 xxx】），助手跑 `node scripts/list-annotations.mjs` 定位，统一处理并删除标注；编辑器保存时会显示剩余标注数，发布前必须清零。
4. **外部审查**：按第七节模板拿给其它模型；意见回来先核实事实再采纳，不逐条盲从。
5. **定稿后**：把新提炼的通用经验回填到本文；个别意见的原始记录写进 `docs/reviews/`。

## 二、文风与结构

**作者明确否决（不要再犯）：**

- 报告腔开场、术语罗列、编年史平铺——评价是"枯燥、平淡、记不住"；
- 手绘风 AI 插图（圆角卡片 + 渐变配色）——"一股 AI 味"；
- Graphviz 学术框图——"还不如上一版"；
- 图文重复（正文句子复述图中文案）。

**作者认可的写法：**

- 开场用具体场景或事件做钩子（股灾、家族群转发），并尽早给出全篇核心判断或关系图，不迟迟不点题；
- 口语化叙述、对读者说话（"做个小实验""先回答前面埋下的问题"）；
- 每节结尾一句加粗记忆点；公式化记忆点必须能排除最明显的反例；
- 一个众所周知的主线例子贯穿全文（如 DeepSeek 的四副面孔：公司 / 模型 / 产品 / agent），辅以多元锚点（验证码、智能音箱、AutoGPT）；
- 大事记、概念对照用表格；延伸阅读每条带可读的链接文字；
- 结尾只收束一次（下篇预告 + 个人化题外话）；大事记、延伸阅读等资料类内容放在正文之后。

## 三、事实与概念红线

- 日期、数字、版本号、型号动笔前**搜索核实**；区分"命名 / 成立 / 发布 / 首发 / 更新"（AI 定名于 1955 提案、1956 是会议；DeepSeek-V4.1-Flash ≠ V4.1-Flash-1017）。已核实例：GPT-6 Astra、GPT-6.1 Sol（2026-09），DeepSeek-V4.1-Flash（2026-10）。
- 增长数据注明口径（注册 vs 活跃；官方 vs 第三方估算）。
- 删除无判据的绝对化断言：所有 / 第一次 / 最早 / 全 / 差一个数量级 / 可判定。
- 转述论文、公司文档不超出原文范围；一家之言标明是一家之言。
- 关键术语先给"本文工作定义"再用；领域 / 方法 / 模型 / 产品的包含关系先画清楚，不写成代际替换。
- 品牌名不当技术类别用；对比前固定变量（版本 / 量化 / 权限）并写明；多因事件用"关键因素之一"。
- 没有出处的具体事故情节删掉，换成文档可查的表述。
- 图里有多个带年份的条目时，按阅读顺序检查年份单调性。
- 接入方式、兼容性示例查官方文档；示例里的型号写全。

## 四、配图生产与展示

**生产：**

- 信息图不手写 SVG、不用 Graphviz（前者 AI 味重、后者太学术），交给专门的图像生成模型，提示词由助手撰写；
- 提示词四要素：① 风格锚点（扁平杂志风，参考 Stripe 博客插图；禁手绘感 / 3D / 照片 / emoji）② 中文标签逐字写死（生成后逐字核对）③ 构图与阅读流向 ④ 3:2 比例、浅灰白底（#F7F9FC）+ 靛蓝主色（#4255CF）贴合站点配色；
- 每张生成 2~4 张挑最好；文字易崩时在提示词末尾加"所有文字位置留白，后期添加"；
- 吉祥物 / 立绘：提示词带统一角色描述段（发色、服饰、五官逐项写死）保证跨图一致；工具支持垫图时用已定稿的图当参考；
- 文件放 `public/images/posts/<slug>/`，语义化命名；列表页封面走 `metadata.cover`；
- 封面图单独出图，不用文内信息图充当：列表封面是 4:3 小缩略图，信息图缩小后文字会糊掉；封面用 4:3 比例、大元素 + 极少文字（如标题关键词卡片），提示词里明确"4:3 横版"与"全图唯一文字"。

**展示（样式类已定义在 globals.css）：**

- 方形立绘 `.article-mascot`（右浮动）/ `.article-mascot-left`（左浮动），左右交替；必须插在"后面还有足够正文"的位置，否则清除浮动的元素会留下一列空白；
- 横版场景图 `.article-mascot-wide`：全宽展示，与信息图同宽；
- 信息图：全宽展示；
- 小屏（≤640px）立绘自动回退为居中，不环绕；
- 纯文本伪代码块用浅色卡片（`pre.language-text`），带语法高亮的代码块保持深色。

## 五、排版硬规范

- 全文中文全角标点。例外：代码块、Markdown 链接语法 `](https://…)`、比分（0:3）、frontmatter 的 JS 语法；
- 段首空两格（全角空格 ×2）；标题、列表、表格、代码块、图片行不缩进；
- 批量转换标点用脚本做邻接判断，转换后必须 grep 检查 `](https` 未被破坏（级联转换曾误伤过链接语法）；
- alt 文本写画面实际内容，不写"应该有"的内容；
- 标题采用「主标题：副题」结构：移动端（≤700px）会在全角冒号后自动强制换行（`post-content.tsx` 的 `title-break`），避免词组被从中间拆开；桌面端宽度足够时不受影响；
- 发布前运行 `node scripts/compress-images.mjs`：`public/images/posts` 下的 PNG/JPG 会等尺寸转为 WebP（最宽 1600px、质量 82）并替换原文件，正文引用需同步改后缀；可重复运行，已是 WebP 的自动跳过。

## 六、本地编辑器与工具

- dev-only 文章编辑器：文章页右下角"✎ 编辑本文（仅本地）"→ 源码面板 → 保存写回 MDX → 热更新；生产构建无按钮、保存 API 返回 404，勿在生产环境暴露任何写接口；
- 面板宽度 32vw（纯视口占比），编辑区自动换行（pre-wrap）；
- 文章里有未处理的【】标注时，编辑按钮会显示数量；面板里"高亮标注"可在渲染页面上黄底标出所有标注位置，方便定位上下文；
- 标注定位：`node scripts/list-annotations.mjs`。

## 七、外部审查提示词模板（要点）

按以下顺序组织提示词，发给具备领域知识的其它模型：

1. 角色与时间锚点：资深中文科技编辑 + 领域专家；声明当前日期与"文中最新型号以当前时点为准"；
2. 文章背景：主题、目标读者、作者目标、配图不可见（alt 已说明）；
3. 审查维度：事实核查（把关键日期、数字、型号逐一列出让它核对）、概念严谨性、结构与流畅度、例子与类比、语言表达、标题与开头；
4. 输出格式：P0 / P1 / P2 三档；每条"原句摘录 → 问题 → 可直接替换的改写"；禁空评；末尾给 150 字内总评与"可否发布"结论；
5. 免检清单：作者排版规范（段首缩进、中文标点、比分半角）、刻意简化的伪代码、其它有意为之的细节；
6. 有文件读取能力的模型直接给文章绝对路径；纯对话模型贴全文。

意见回来后：先按第三节红线核实（尤其是它给出的"正确说法"），采纳的统一修改，不逐条盲从。

## 二、会话二：复审新增的 7 条（完整记录）

### P0（必须改）

**1. 模型演变图的年份阅读顺序会教错历史**
- 问题：卡片顺序为规则→机器学习→深度学习→大语言模型，但第一张卡的里程碑是 1965（DENDRAL），第二张卡是 1959（Samuel），按阅读顺序年份倒挂，读者会得出"专家系统先于机器学习"。
- 修复：第一张卡补"1956｜'逻辑理论家'问世"（Logic Theorist，公认第一个 AI 程序，规则推理系统），DENDRAL 1965 保留为第二行；年份顺序恢复单调（1956→1959→2012→2017/2020）。
- 规则：**图里有多个带年份的条目时，按阅读顺序检查单调性；卡片顺序与年代顺序冲突时，补更早的代表性事件而不是改卡片顺序。**
- 流程教训：先做过一版像素级修补，作者随后用原生重渲染版本替换——**修图优先整图重渲染，像素修补只是兜底**。

### P1（明显建议改）

**2. "R1 接进 Codex 自动改代码"的示例缺少依据**
- 问题：DeepSeek 官方 Codex 接入指南只提供 `deepseek-flash`（由 V4.1-Flash-1017 支持）与 `deepseek-v4-pro`，不含 R1（已回查官方文档核实）。
- 修复："四副面孔"段的 agent 示例改为"把 V4.1-Flash 接入 Codex、配上工具与自主执行循环"。
- 规则：**产品接入、兼容性类的具体示例必须有官方文档支撑；正文里随手举的例子和正式声明一样需要核实。**

**3. 智能音箱的限定差最后一步**
- 问题：前文已正确区分宽泛 agent 与大模型 Agent，但"音箱属于后者，顶多算语音遥控器"又把所有音箱按硬件形态归入固定流程。
- 修复：实验限定为"小爱同学、天猫精灵这类主要依靠预设技能工作的传统智能音箱"；结论改为"如果只是识别意图、调用预设技能，就更像语音遥控器，还不具备本文讨论的自主任务执行能力"。
- 规则：**硬件形态不能决定软件架构；下判断的条件（预设技能 vs 自主决策）要写进限定语里。**

**4. Harness 记忆句混用"DeepSeek"的三层含义**
- 问题："Harness 不是 DeepSeek 的一部分"里的 DeepSeek 指模型权重，但本文刚强调这个词也指公司和产品；官方产品中的 harness 完全可以由深度求索开发。
- 修复：改为"Harness 是模型权重之外、组织模型运行的那部分系统；它可以由深度求索官方提供，也可以由第三方开发"；总结表 Harness 示例从"ChatGPT 的对话层、Codex、Agent SDK"改为"Claude Agent SDK；Codex 中的工具、上下文管理与执行控制机制"。
- 规则：**多义词（公司/模型/产品）做判断时，先换成无歧义的那个含义再说；整个产品与其中的运行框架不要混为一谈。**

**5. 官网与编码工具的对比应限定为"主动访问"**
- 问题："连你电脑的一个文件都碰不到"忽略了网页产品可以处理用户上传的文件；编码工具也需要授权。
- 修复：改为"只在官网聊天、没有开放本地访问权限时，它不能主动浏览你的代码目录；接入具备文件和终端工具的编码 Agent 后，它才可以在授权范围内读取代码、修改文件、运行测试"。
- 规则：**能力对比落在"是否被授权主动访问环境"，而不是"能不能碰文件"这种可被反例推翻的粗话。**

### P2（可选优化）

**6. "一门研究领域"量词搭配错误**
- 修复："AI 是一个研究领域"；并加"可以组成能够自主推进任务的 Agent"，避免暗示任何模型套上框架都自动成为 Agent。
- 规则：**量词搭配（一个领域/一门学科）单独读一遍就能查出来；"A 加 B 就成为 C"的句式检查是否把必要条件写成了充分条件。**

**7. 演进段太密，分类关系应前置**
- 问题：关系说明放在段尾，读者要读完专家系统/AlexNet/Transformer/规模定律再回头理解；"层层相承"对规则系统与机器学习不准确。
- 修复：段首先摆关系（深度学习属于机器学习、主流大语言模型采用深度学习、规则系统可与之配合），再按"规则与机器学习 → AlexNet → Transformer 与规模定律"拆三个自然段。
- 规则：**一段承担两个任务（叙事 + 分类）时，先给分类框架再叙事；对不含继承关系的对象不用"相承"类动词。**

## 三、通用检查清单（写其它文章时过一遍）

**事实与口径**
- [ ] 每个日期、数字、版本号回查原始来源；区分命名/成立/发布/首发/更新
- [ ] 增长或规模数据注明口径（注册 vs 活跃；官方 vs 第三方估算）
- [ ] 模型的输入模态、自身知识、外部权限分开说，不混成一个"能力"
- [ ] 开放性用准确词（开放权重 / 开源许可 / API 可用）
- [ ] 转述论文或公司文档不超出原文范围；一家之言标明是一家之言

**概念与边界**
- [ ] 领域 / 方法 / 模型 / 产品的包含关系先画清楚，不写成代际替换
- [ ] 关键术语给"本文工作定义"，并让图、表、正文共用同一划分
- [ ] 记忆点公式要能排除最明显的反例（如 workflow 也有工具和循环）
- [ ] 品牌名不当技术类别；按交互方式或架构特征分类
- [ ] 删除无判据的"所有 / 第一次 / 最早 / 全 / 差一个数量级 / 可判定"

**论证与示例**
- [ ] 接入方式、兼容性示例查官方文档；版本号写全
- [ ] 对比前固定变量（版本 / 量化 / 推理设置），并写明
- [ ] 删掉无出处的具体事故情节，换成文档可查的表述
- [ ] 多因事件收敛归因（"关键因素之一"），比喻在全文保持同一结构

- [ ] 修图优先整图重渲染；像素修补前确认有 git 备份

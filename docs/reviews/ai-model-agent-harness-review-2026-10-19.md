## P0：事实错误或概念冲突，必须改

### 1. 智能音箱不能被一概排除在 Agent 之外

**原句：**

> 它没有循环，没有自主决策。所以它不是 Agent，顶多算一个语音遥控器。

**问题：**这与下一段引用的 Russell、Norvig 定义冲突。按“感知环境并采取行动”的宽泛定义，智能音箱可以被视为 agent；教材也包含简单反射式 agent，并不要求复杂规划。无法完成账单任务，也不足以证明它不是 agent。这里需要限定为本文讨论的“大模型自主智能体”。[教材原文](https://aima.cs.berkeley.edu/4th-ed/pdfs/newchap02.pdf)

**替换：**

> 这里讨论的，是由大模型自主推进任务的 Agent。如果一个音箱只是识别意图、调用预设技能，它就还不具备这种自主性。判断关键在于：下一步由模型根据反馈决定，还是由预设流程安排。

小标题同步改为：**“Agent：从听懂指令到自主推进任务”**。

### 2. 总关系图把 Agent 与 Harness 画成了边界不清的两层

**原文图注：**

> 四个概念的关系：AI 学科一路收窄出大语言模型，模型装进 Agent，Agent 外面再包一层 Harness，最后作用于真实环境

**问题：**后文已经把工具层、主循环算进 harness，而 Agent 的定义又包含工具与循环。“Agent 外面再包 Harness”因此形成重复包含。不同作者可以采用不同划分，但本文必须自洽；harness 也不必等到“生产级包装”才出现。

**替换：**

> 四个概念的关系：AI 是研究领域；大语言模型提供理解与生成能力；Harness 提供工具、上下文管理和运行控制；模型与这些机制共同组成能够自主推进任务的 Agent。

需要同步修改关系图中的概念关系，不能只改 alt。

### 3. “模型”的定义过窄，训练数据的描述也不成立

**原句：**

> 一句话：一大团参数构成的函数，文本进，文本出。
>
> 它读遍了整个互联网，聊天、写代码、做翻译样样精通——但它没有手。

**问题：**“文本进、文本出”只适合本文选定的文本模型示例，不能定义所有模型。文中列出的 V4.1-Flash 本身支持视觉输入。“读遍整个互联网”也不成立：训练使用的是选取、过滤后的数据，不是整个互联网。输入模态与访问电脑的权限，更是两个独立问题。[V4.1-Flash 官方说明](https://www.deepseek.com/en/news/deepseek-v4-1-flash/)

**替换：**

> 本文主要讨论大语言模型：它由网络结构和训练得到的参数组成，根据输入生成后续内容；多模态模型还可以处理图像、音频等。训练让它学会了语言、代码和许多知识，但主动读取文件、运行程序，还需要外部系统提供工具和权限。

总结表中的“参数化的函数，文本进文本出”同步改为：**“通过训练获得能力的计算模型，本文主要讨论大语言模型”**。

### 4. 规则、机器学习、深度学习、LLM 不是依次替代的“四代”

**原句：**

> 七十年里实现手段换了四代，目标本身没变过。

**原文图注：**

> 模型演变四阶段：写规则的专家系统、机器学习、深度学习、大语言模型

**问题：**这里混合了历史顺序与分类关系。深度学习属于机器学习，当下主流 LLM 采用深度学习；规则系统也没有被淘汰。写成“四代”“四阶段”，容易让读者记住错误的技术谱系。另外，AI 首先是一门研究领域，不能只定义为一个目标。

**替换：**

> AI 是研究如何让机器表现出智能的一门学科。从规则系统到机器学习，再到深度神经网络和大语言模型，研究重点不断变化，但这些方法长期并存。深度学习属于机器学习，当下主流的大语言模型采用的正是深度学习方法。

**图注替换：**

> 从规则系统到大语言模型的技术脉络：方法长期并存，机器学习、深度学习与主流大语言模型之间存在包含关系。

### 5. “Artificial Intelligence”命名时间应为 1955 年

**原句：**

> "Artificial Intelligence"这个名字，要到 1956 年的达特茅斯夏季研讨会才被造出来（项目提案上署名的还有信息论之父香农）。

**问题：**会议是 1956 年，但这个名称已经出现在 **1955 年 8 月 31 日**的项目提案中。文章自己的延伸阅读也标注了 1955 年，构成内部矛盾。[提案原文](https://www-formal.stanford.edu/jmc/history/dartmouth/dartmouth.html)

**替换：**

> “Artificial Intelligence”这个名称，已出现在麦卡锡等人于 1955 年提交的达特茅斯夏季研究项目提案中，香农也是署名者之一。1956 年举行的研讨会，则通常被视为人工智能作为独立研究领域诞生的标志。

大事记的“1956／正式定名”同步改为：**“1956／达特茅斯会议／通常被视为 AI 学科诞生的标志”**。

### 6. Master 连胜跨年，柯洁落泪的先后顺序也写错了

**原句：**

> 同年年底它的升级版 Master 在网上横扫 60 连胜，2017 年柯洁 0:3 认输后当场落泪。

**问题：**Master 的 60 连胜发生于 **2016 年底至 2017 年初**，不能全部放进“同年年底”。柯洁三番棋总比分 0:3 正确，但新华社记录的是他在第三局**比赛中**落泪，不是总比分确定后才落泪。[AlphaGo Master 相关论文](https://ai6034.mit.edu/wiki/images/Nature24270_AlphaGoZero.pdf)、[新华社现场报道](https://photo.china.com.cn/news/2017-05/28/content_40914317.htm)

**替换：**

> 2016 年底至 2017 年初，升级版 Master 在网上取得 60 连胜。2017 年 5 月，柯洁在乌镇三番棋中以 0:3 告负，并曾在第三局比赛中落泪。

### 7. Transformer 不是“所有大模型”的共同底座

**原文表格：**

> 2017 | Transformer | 今天所有大模型的共同底座

**问题：**“所有”不成立。大模型也包括其他模态和架构；即使限定语言模型，也存在 Mamba 等不同路线。[Mamba 原论文](https://arxiv.org/abs/2312.00752)

**替换：**

> 2017 | Transformer | 成为此后大多数主流大语言模型的架构基础

## P1：明显建议改，影响可信度或理解

### 8. ChatGPT 增长数字应注明统计口径

**原句：**

> 2022 年 11 月 30 日，ChatGPT 上线，五天百万用户，两个月破亿。

**问题：**上线日期正确。“五天百万”指注册用户；“两个月破亿”通常引用 UBS 基于 Similarweb 数据作出的月活估算。直接连写，会让人误以为两者是同一口径的官方统计。[OpenAI 用户研究](https://cdn.openai.com/pdf/a253471f-8260-40c6-a2cc-aa93fe9f142e/economic-research-chatgpt-usage-paper.pdf)、[Similarweb 说明](https://www.similarweb.com/blog/insights/ai-news/chatgpt-25-million/)

**替换：**

> 2022 年 11 月 30 日，ChatGPT 上线，五天内注册用户突破百万；据 UBS 基于 Similarweb 数据的估算，到 2023 年 1 月，其月活用户已约达一亿。

### 9. 规模定律没有承诺“各种能力都能预测增长”

**原句：**

> 最后是大语言模型：2017 年 Google 那篇《Attention Is All You Need》提出 Transformer 架构，2020 年规模定律又发现模型能力随参数和数据规模可预测地增长——"大力出奇迹"从玄学变成了工程学，1750 亿参数的 GPT-3 就是这份底气的展示品。

**问题：**Transformer 的年份、GPT-3 的 1750 亿参数正确。但所引规模定律研究的是语言建模损失与参数量、数据量、训练计算量的经验关系，不等于所有下游能力都可以预测。“最后”也继续强化了四代替代的误解。[规模定律原论文](https://arxiv.org/abs/2001.08361)、[GPT-3 原论文](https://arxiv.org/abs/2005.14165)

**替换：**

> 在大语言模型这条线上，2017 年提出的 Transformer 成了关键架构。2020 年的规模定律研究进一步发现，语言建模误差会随参数量、数据量和训练计算量呈现较稳定的经验规律，让扩大训练规模有了更可计算的依据。同年，1750 亿参数的 GPT-3 展示了规模扩大带来的能力提升。

### 10. AlexNet 的意义不是让人从此“只管喂数据、堆显卡”

**原句：**

> 接着深度学习把这件事推到极致——2012 年 AlexNet 在图像识别大赛上把错误率大幅甩开对手，从此连"看哪些特征"都交给多层网络自己学，人只管喂数据、堆显卡。

**问题：**年份和突破方向正确，但自动学习特征并非从 AlexNet 才开始；模型结构、训练方法、数据处理也没有因此变得无关紧要。最后半句会把后面反对“光有模型”的论证先削弱掉。[AlexNet 原论文](https://papers.nips.cc/paper/4824-imagenet-classification-with-deep-convolutional-neural-networks)

**替换：**

> 2012 年，AlexNet 在 ImageNet 图像识别竞赛中大幅领先对手，让深度学习受到广泛关注。相比大量手工设计特征，多层神经网络能从数据中学习更有效的表示，但数据、网络结构和训练方法仍然至关重要。

### 11. 深蓝与 AlphaGo 的对比过于二分

**原句：**

> 但深蓝赢棋的办法说穿了并不优雅——暴力穷举加上人类棋手手写的评估函数，一台"下了魔的国际象棋专用超算"。
>
> 2016 年 AlphaGo 战胜李世石，靠的是深度神经网络加强化学习，自己跟自己下了几百万盘棋。

**问题：**深蓝不是穷尽所有棋局，而是高速搜索结合选择性扩展、评估函数和棋类知识。AlphaGo 也依赖树搜索，早期系统还使用了人类棋谱。“几百万盘”未交代版本及出处；2016 年论文中，价值网络训练数据就涉及从 3000 万盘独立自对弈中抽取局面，不能随意概括成这个数字。[深蓝团队论文](https://research.ibm.com/publications/deep-blue)、[AlphaGo 原论文](https://storage.googleapis.com/deepmind-media/alphago/AlphaGoNaturePaper.pdf)

**替换：**

> 深蓝把高速搜索、人工设计的评估函数和棋类知识结合起来，是经典搜索工程的代表。2016 年战胜李世石的 AlphaGo，则结合了深度神经网络、从人类棋谱中学习、自我对弈强化学习，以及蒙特卡洛树搜索。变化在于，越来越多的判断能力可以从数据和对弈中学出来。

### 12. Agent 的记忆公式漏掉了最关键的“自主决策”

**原句：**

> Agent = 模型 + 工具 + 循环 + 目标。模型负责想，工具负责做，循环负责连，目标负责停。

**问题：**固定 workflow 同样可以有模型、工具、循环和目标，四项相加不足以区分 Agent。“目标负责停”也容易让人误以为目标会自动提供可靠的完成判断。

**替换：**

> 本文讨论的大模型 Agent，是由模型自主决定下一步、借助工具并根据反馈持续推进目标的系统。模型负责决策，工具执行动作，循环带回反馈，目标给出方向；是否继续，还要看验收结果、预算和人工控制。

总结表中的 Agent 定义也应加入“模型自主决定下一步”。

### 13. Anthropic 的 workflow 转述把简化建议说偏了

**原句：**

> 代码写死的流程叫 workflow，模型只是流水线上的工人；模型自己在循环里决定下一步怎么干，才叫 agent。
>
> 他们的建议也很实在：能简单就别复杂，大多数活儿，编排好的 workflow 就够用。

**问题：**workflow 可以包含条件分支、模型路由、评估循环，并非“写死”到不能变化。原文也没有统计意义上的“大多数活儿都用 workflow”；它明确说，许多应用优化单次模型调用就够了。这是一家公司的架构辨析，也不宜写成全行业唯一判据。[Anthropic 原文](https://www.anthropic.com/engineering/building-effective-agents)

**替换：**

> Anthropic 在文中采用了一种架构区分：workflow 由预先设计的代码路径编排模型和工具；agent 则让模型动态决定处理过程和工具使用。他们建议从最简单的方案开始：许多应用用一次配合检索和示例的模型调用就够了，需要更多步骤时再考虑 workflow 或 agent。

### 14. “直接搬来强化学习循环”缺少历史依据

**原句：**

> 于是人们把强化学习里那个现成的循环直接搬过来，给模型挂上工具：

**问题：**这是把结构相似写成了明确的技术继承关系。大模型 Agent 的推理执行循环，既不必使用强化学习训练，也不必在运行中更新参数。

**替换：**

> 一种自然的做法，是让模型也进入“观察—行动—反馈”的循环：给它工具，让它根据执行结果决定下一步。这样的执行循环不要求模型在运行时继续学习。

### 15. AutoGPT 的失败故事写得像有出处的具体事件

**原句：**

> 2023 年春天，AutoGPT 火遍全网——普通人第一次看见"模型自己拆任务、自己找工具、自己迭代"，也第一次看见它翻车：给它定个"赚钱"目标，它真能自己写邮件、自己建项目，一晚上烧掉可观的 API 费，最后一事无成。

**问题：**“普通人第一次”无法支撑；赚钱、邮件、烧一晚费用这一串细节，读起来像特定实录，却没有来源。项目早期文档确实强调实验性质和运行费用，可以据此写，没必要虚构一个完整事故。[AutoGPT 早期 README](https://raw.githubusercontent.com/Significant-Gravitas/AutoGPT/v0.2.0/README.md)

**替换：**

> 2023 年春天，AutoGPT 让“模型自行拆解目标、调用工具、反复尝试”的演示受到广泛关注。但演示离可靠交付还有距离：目标可能迟迟无法完成，连续调用又会不断产生费用。项目早期文档也明确提醒，它仍是实验，运行成本需要监控。

时间线建议把这一项移到 2023 年 6 月 function calling 之前，避免顺序倒退。

### 16. 官网、本地、API 并不能直接证明“差别全在外围”

**原句：**

> 模型是同一只，体验天差地别。差别不在模型，全在外围那层东西给了它什么提示词、什么工具、什么权限。

**问题：**这三个入口未必使用相同版本、完整权重、量化精度和推理设置。本地 Ollama 里的蒸馏版或量化版，尤其不能直接当作同一个受控变量。这个例子能够说明外围系统重要，证明不了差别“全”来自外围。

**替换：**

> 在固定模型版本、量化精度和推理设置之后，外围系统提供的提示词、工具、上下文管理和权限，仍会明显改变体验。官网、本地部署和 API 未必使用同一套模型配置，比较前先确认引擎是否一致。

### 17. Harness 的起源与“行业标准”都说得过满

**原句：**

> 这个词最早在评测圈用开：EleutherAI 的 lm-evaluation-harness 把"模型"和"怎么测模型"拆开，同一套框架能套在任何模型外面跑分。
>
> 到 2025 年编码智能体爆发，"agent harness"成了行业标准叫法：包住模型、让它真正能干活的整套工程。

**问题：**所引项目能证明评测领域存在这种用法，证明不了“最早”；“任何模型”也超出了实际接口兼容范围。“行业标准叫法”容易被理解为已有统一规范，而本文恰恰需要主动约定边界。[评测框架说明](https://github.com/EleutherAI/lm-evaluation-harness)、[Anthropic 对 agent harness 的使用](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)

**替换：**

> 在模型评测中，EleutherAI 的 lm-evaluation-harness 就用这个词指代统一组织评测任务、对接不同模型的框架。编码智能体兴起后，agent harness 也成为常见用语。本文用它指支撑模型持续执行任务的工具、上下文管理与运行控制机制。

### 18. “差一个数量级”缺证据，“各占几成”无法直接拆分

**原句：**

> 因为同一个模型，换一套 harness，成绩能差出一个数量级。
>
> 所以以后看榜单，记得多问一句：这成绩里，模型占几成，Harness 占几成？

**问题：**“一个数量级”通常意味着约十倍，需要提供具体模型、任务和实验配置。模型与 harness 又存在交互作用，不能从总分拆出贡献百分比。SWE-bench 的不同视图还可能固定同一套 agent 环境，需要区分评测设置。[SWE-bench 官方说明](https://www.swebench.com/)

**替换：**

> 同一模型在不同 harness 和预算下，成绩可能明显变化。看 SWE-bench 这类榜单时，应同时核对模型版本、任务子集、harness、工具和尝试预算；单个总分无法告诉你模型与工程各占几成。

### 19. “发动机／整车”需要修正，Agent SDK 也不是直接卖整车

**原句：**

> 类比还是那句话：模型是发动机，Harness 是整辆车——发动机决定上限，车决定你敢不敢上路。
>
> 2025 年 Anthropic 干脆把自家验证过的 harness 打包成 Claude Agent SDK 卖给开发者：发动机大厂开始卖整车，这大概是 harness 重要性的最好注脚。

**问题：**“整辆车”包含发动机，与前文“模型之外的部分”冲突；“发动机决定上限”也掩盖了系统协同。SDK 提供可复用的基础能力，还需要开发者构建产品。“卖”则混淆了 SDK 的提供与模型服务的收费。官方事件更准确地说，是 **2025 年 9 月 29 日将 Claude Code SDK 更名为 Claude Agent SDK**。[官方文章](https://claude.com/resources/articles/building-agents-with-the-claude-agent-sdk)

**替换：**

> 沿用汽车的比喻：模型是发动机，harness 像传动、转向、制动和控制系统，它们配合起来才决定车辆的实际表现。2025 年 9 月，Anthropic 将 Claude Code SDK 更名为 Claude Agent SDK，把支撑 Claude Code 的工具与运行机制提供给开发者，用来构建不同类型的 Agent。

记忆句相应改为：**“模型提供动力，Harness 把动力组织成可控的行动。”**

### 20. ChatGPT、Copilot、Agent 不是互斥的产品类别

**原句：**

> 顺手把几个邻居也分清楚：模型加对话界面是聊天助手（ChatGPT）；模型在编辑器里打字辅助是 Copilot；模型在循环里自己决策干活，才是 Agent；而 Agent 加上生产级的工程包装，才是 Claude Code、Codex 这种能签收需求的产品。

**问题：**把品牌名称当成技术类别，到了 2026 年尤其容易过时。ChatGPT 已有 Agent 功能，GitHub Copilot 也有 coding agent；对话界面并不排斥自主执行。“Agent 加生产级工程才成为产品”又重复了前面的边界冲突。[ChatGPT agent 发布说明](https://openai.com/index/introducing-chatgpt-agent/)、[GitHub Copilot coding agent 文档](https://docs.github.com/en/copilot/concepts/agents/about-copilot-coding-agent)

**替换：**

> 聊天、代码补全和自主执行，是不同的交互方式，同一个产品可以同时提供几种。ChatGPT 和 GitHub Copilot 都能包含 Agent 功能；Claude Code、Codex 则把 Agent 式任务执行作为核心体验。判断时看实际运行方式，比看产品名称更可靠。

### 28. 收尾出现多次，最后一段可以改成实际判断方法

**原句：**

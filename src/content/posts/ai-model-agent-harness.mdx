# AI、模型、Agent、Harness：四个词的前世今生

## 一个越来越吵的词汇现场

过去两年，你大概听过不少这样的句子："给模型接个 Agent"、"换个 Harness 跑分高了一截"、"现在人人都在做 Agent 创业"。听起来每个词都认识，连在一起又说不清到底谁在干什么。

这不怪读者。这几个词本来就不属于同一个层面——有的是学科的名字，有的是一样东西的名字，有的干脆是一层"包装"的名字。媒体和营销又惯常地把它们搅在一起，什么都能叫 AI，什么也都敢叫 Agent。

这篇文章想把这四个词放回它们各自的历史里，按时间顺序讲三件事：它指什么、从哪来、后来怎么演变成今天的样子。先上一张全篇的地图，后文逐块展开。

![四个概念的关系全景图：AI 一路收窄到具体模型；Agent 由模型、工具、循环组合而成，外面再包一层 Harness](/images/posts/ai-model-agent-harness/concept-map.svg)

一句话剧透：**AI 是领域，模型是引擎，Agent 是会干活的"员工"，Harness 是把引擎接上现实的那套马具。**

## AI：一个坚持了七十年的名字

1950 年，图灵在哲学期刊《Mind》上发表了[《Computing Machinery and Intelligence》](https://doi.org/10.1093/mind/LIX.236.433)。他没有正面回答"机器能不能思考"，而是换了一个可操作的问题——如果一台机器在对话里让人分不清它是人还是机器，我们该不该承认它在"思考"？这就是著名的图灵测试。把一个哲学争论改写成可以判定的实验，是这篇文章最了不起的地方。

"Artificial Intelligence"这个名字，则要到 1956 年的达特茅斯夏季研讨会才诞生。约翰·麦卡锡在[项目提案](https://dl.acm.org/doi/10.1145/365866.365868)里造了这个词，同署名的还有明斯基、香农这些后来各自开宗立派的人物。这次会议没产出什么惊人的成果，但它给了整个领域一个名字，一群人从此有了共同的旗号。

![AI 历史时间轴：1950 图灵测试、1956 达特茅斯会议、1997 深蓝、2012 AlexNet、2017 Transformer、2022 ChatGPT、2025 编码 Agent](/images/posts/ai-model-agent-harness/ai-timeline.svg)

此后七十年的主线，可以粗略概括为两条路线的竞争与轮替：

- **符号主义**：智能来自对知识和逻辑规则的显式表达，代表作是专家系统。1997 年打败国际象棋世界冠军卡斯帕罗夫的深蓝，可以看作这条路线的高光——本质上是暴力搜索加上人类棋手精心设计的评估函数。
- **连接主义**：智能从大量简单单元的连接中"长"出来，也就是神经网络。这条路冷了几十年，直到 2012 年 AlexNet 在 ImageNet 竞赛上把错误率大幅甩开第二名，深度学习加上 GPU 加上海量数据的组合才正式接管主线。2016 年 AlphaGo 战胜李世石，连"智力的高地"围棋也被拿下，而这一次靠的是深度神经网络与强化学习。

中间还夹着两次"AI 寒冬"（大约 1974–1980 和 1987–1993）：承诺兑现不了，经费和热度一起退潮。期望与现实的落差周期，后来反复上演，只是每次的剧情略有不同。

所以要给 AI 一个准确的定位：它不是某一样东西，而是一个**目标**——"让机器表现出智能"——以及围绕这个目标形成的整个学科。七十年来实现目标的手段换了一代又一代，目标本身没变过。

## 模型：从"写规则"到"学函数"

早期 AI 的思路是人写规则：把专家的知识一条条录入，机器照着推理。这条路在封闭的小领域里能跑，但知识靠人喂，规则之外就无能为力。

真正的转折是一种朴素的想法：与其把答案教给机器，不如给它看大量例子，让它自己**学出一个函数**——这就是机器学习。深度学习再把这件事推到极致：连"看哪些特征"都让多层网络自己学，人只负责喂数据和堆算力。

![模型演变四阶段：写规则的专家系统、机器学习、深度学习、大语言模型](/images/posts/ai-model-agent-harness/model-evolution.svg)

2017 年，Google 的八位研究者在[《Attention Is All You Need》](https://arxiv.org/abs/1706.03762)里提出 Transformer 架构。它的关键贡献是自注意力机制——序列里每个位置都可以直接"看到"其他所有位置，而且整个计算可以大规模并行。今天的几乎所有大语言模型，底座都是它。

接下来的故事是"大力出奇迹"有了理论依据：2020 年 OpenAI 的[规模定律](https://arxiv.org/abs/2001.08361)显示，模型能力随参数、数据、算力的增长可预测地提升；同年 1750 亿参数的 [GPT-3](https://arxiv.org/abs/2005.14165) 展示出少样本学习能力——不用重新训练，给几个例子它就能照着做新任务。2022 年，经过人类反馈强化学习（RLHF）对齐的 InstructGPT 路线被产品化，ChatGPT 在 2022 年 11 月 30 日上线，模型的能力第一次被数亿普通人直接摸到。

把这些收拢起来，"模型"到底是什么：**一大团参数构成的函数，输入文本，输出文本。** 它读遍过整个互联网，聊天、写作、写代码样样在行——但它没有手脚：读不了你磁盘上的文件，跑不了命令，不知道现在几点，甚至算错数也不会自己去查。它只负责"想"，不负责"做"。

## Agent：给模型装上手脚

"Agent"这个词比大模型老得多。它来自拉丁语 *agere*，意思是"去做"，直译就是"行动者"。

学界很早就有严格定义。1995 年Russell 和 Norvig 的经典教材《人工智能：现代方法》里写道：**凡是能通过传感器感知环境、并通过执行器对环境产生作用的，都是 agent。**明斯基 1986 年的《心智社会》则提出，人类智能本身也是无数简单"小 agent"协作的涌现结果。后来强化学习把"agent–环境循环"变成了标准术语：agent 观察状态、做出动作、环境反馈奖励，如此往复——2015 年 DeepMind 用这套循环让机器学会打 Atari 游戏、下围棋，agent 一词在学术界彻底扎根。

大模型登场时，戏剧性的一幕出现了：模型自己会"说"了，但依然不会"做"。于是人们把上面那个七十年沉淀下来的循环直接搬过来，给它装上了工具：

- 2022 年 10 月，[ReAct](https://arxiv.org/abs/2210.03629) 论文让模型交替进行"推理"和"行动"——想一步，调一次工具，看一眼结果，再想下一步。
- 2023 年 2 月，[Toolformer](https://arxiv.org/abs/2302.04761) 展示了模型可以在训练中学会自己插入 API 调用。
- 2023 年 6 月，OpenAI 把 function calling 做成了 API 的标准能力，"模型报出工具名和参数、程序负责执行并把结果传回去"从此成为通用模式。
- 2023 年春天，AutoGPT 火遍全网：普通人第一次看到"模型自己拆任务、自己找工具、自己迭代"。热潮同时也暴露了致命问题——幻觉会累积，循环会失控，模型一个人跑不远。**光有聪明的模型和工具还不够，缺的是工程。**

![Agent 循环：目标进入模型，模型决定行动，工具执行并返回结果，观察写回上下文，循环直到完成](/images/posts/ai-model-agent-harness/agent-loop.svg)

把循环写成伪代码，其实就是这么几行：

```text
while (目标未完成) {
    思考   = 模型(目标, 历史记录, 工具返回值)
    行动   = 选择一个工具(思考)
    返回值 = 执行工具(行动)
    历史记录 += [思考, 行动, 返回值]
}
```

值得注意的是，这个循环和强化学习里那个七十年沉淀下来的 agent–环境循环几乎一模一样——同一个词，绕了一大圈又回来了，只是"传感器"换成了工具的返回值。

2024 年底，Anthropic 在[《Building effective agents》](https://www.anthropic.com/engineering/building-effective-agents)里给出了一组至今被广泛引用的辨析：**workflow** 是代码写死的编排流程，模型只是流程里的环节；**agent** 才是模型自己在循环里自主决定下一步怎么做。他们的建议也很克制：能简单就别复杂，绝大多数场景一个编排好的 workflow 就够。这段话后来成了很多团队做 agent 设计的"压舱石"。

所以我对 Agent 的总结是一行公式：**Agent = 模型 + 工具 + 循环 + 目标。** 模型负责想，工具负责做，循环负责串起来，目标负责让它停下来。

## Harness：藏在 Agent 背后的马具

Harness 本义是马具、挽具——把动力（马）和执行（车）连接起来的那套皮带与挽索。工程领域的引申义也一直如此：**包住核心动力、让它能真正运转起来的一整套外围框架。**

这个词先在评测圈被用开。EleutherAI 开源的 [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) 把"模型"和"怎么测模型"分开——同一套测试框架，可以套在任何模型外面跑分。到了 2025 年编码智能体爆发，"agent harness"成了行业里的标准叫法：Claude Code、Codex CLI 这类工具里，真正包住模型的那一整层工程，就叫 harness。

![Harness 解剖图：系统提示词、上下文工程、权限与沙箱、子 Agent 编排、工具层、主循环、错误恢复、记录与评测](/images/posts/ai-model-agent-harness/harness-anatomy.svg)

一个编码 agent 的 harness 里大致装着这些东西：

- **系统提示词**：角色设定、行为规范、安全边界，是模型对"我是谁、我在干嘛"的全部认知来源；
- **工具层**：读写文件、执行命令、搜索代码、打开浏览器，以及子 agent 派发；
- **主循环**：把"模型→工具→结果回填"串起来，处理并发、中断和恢复；
- **上下文工程**：历史裁剪、摘要压缩、记忆文件（比如 `AGENTS.md`、`CLAUDE.md`），让有限的上下文窗口装下最有用的信息；
- **权限与沙箱**：哪些操作自动执行、哪些必须人工确认，文件系统和网络能碰到哪里；
- **错误恢复**：工具调用失败后的重试、回滚和降级；
- **记录与评测**：完整轨迹留档、成本统计、回放调试。

为什么值得专门给它一个名字？因为**同一个模型，换一套 harness，能干成的事可能差一个数量级。** 各类编程榜单上的分数，从来都不是模型单独的成绩，而是"模型 + harness"这个联合体的成绩——工具给得全不全、上下文管理得好不好、循环控制得稳不稳，都直接影响结果。所以以后看到跑分，值得多问一句：这成绩里，模型占几成，harness 占几成？

我的类比是：模型是发动机，harness 是底盘、变速箱和整套车载系统。发动机决定这台车的上限，底盘决定你敢不敢真的开上路。2025 年 Anthropic 推出 [Claude Agent SDK](https://www.anthropic.com/engineering/building-agents-with-the-claude-agent-sdk)，把自家内部验证过的 harness 直接产品化交给开发者——引擎大厂开始卖底盘，这大概是 harness 重要性的最好注脚。

## 四个词，各自归位

回到开头那张地图，现在可以给出每个词的准确定位：

| 概念 | 本质 | 回答的问题 | 一个类比 |
| --- | --- | --- | --- |
| AI | 一门学科、一个目标 | 机器能不能表现出智能？ | "飞天"这个愿景 |
| 模型 | 一大团参数构成的函数 | 由谁来思考？ | 发动机 |
| Agent | 模型 + 工具 + 循环 + 目标 | 谁来把事办成？ | 一位员工 |
| Harness | 包住模型的整套工程框架 | 怎么让它干得成、干得稳？ | 底盘与整车工程 |

几个容易混淆的相邻概念也顺带放进来：模型加上对话界面是聊天助手（ChatGPT）；模型加上辅助性的代码建议是 Copilot；模型加上工具、循环和自主决策才是 Agent；而 Agent 加上生产级的工程包装，才是 Claude Code、Codex 这类能干活的产品。

## 写在最后

理清这四个词，不只是为了聊天时不被术语绕晕。它更像一张地图：AI 告诉你目标在哪，模型告诉你引擎有多强，Agent 告诉你活儿怎么被干成，Harness 则提醒你——**想法和产品之间隔着的，往往不是模型能力，而是这一整层工程。**

下一篇会顺着 harness 往下挖，讲讲今天 AI 使用生态里那些具体名词：Skills、MCP、hooks、插件、子智能体、指令——它们分别解决 harness 里哪一层的问题，以及怎么用起来。

最后说一句题外话：这篇从大纲、配图到成文，就是一个人、一个模型和一套 harness 协作的产物——算是给本文主题现身说法了。

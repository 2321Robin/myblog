# 上手第一个 Agent：从选型到第一次交付的入门路线

## 从朋友的一个问题说起

　　上个月，朋友看我用 Agent 半天干完了他估摸着要磨一天的活儿，凑过来问：“这东西怎么上手？”我脱口而出“简单”，然后打开手机，准备给他推一款 App——卡住了。我要推荐的不是一款 App，而是一整套东西：网页里能聊的、终端里能跑的；有订阅的、有按量付费的；有大陆直接能注册的，也有需要国际支付方式的。十来款产品摆在一起，我先替他头晕了。

　　冷静下来想想，他真正的困惑其实是三个：装哪个？怎么跟它提要求？会不会把文件搞坏、把钱包搞瘪？这篇就照着这三个困惑来组织——外加一条底线：别让教程在收藏夹里吃灰。

　　如果你也被人这样问过，或者收藏夹里躺着几十篇“Agent 入门”却始终没动手，这篇就是写给你的。先把核心判断放在这儿：上手 Agent 不难，难的是两件事——**选对第一站，把需求说清楚**。安装从来不是门槛，一行命令的事；真正的门槛，是你带着什么预期进门。

　　Agent 是什么，上一篇[《AI、模型、Agent、Harness》](/blog/ai-model-agent-harness)已经交代过：下一步由模型自己决定、借助工具持续推进目标的系统。本文不重复定义，直接解决“怎么用起来”。整条路线就五步：

- 第一步，想清楚要它干嘛：查资料、写文案这类轻活，还是要它直接改你的项目；
- 第二步，选第一站：按“写不写代码、在哪付费方便、预算多少”三问对号入座；
- 第三步，装起来：网页端零安装，终端端一行命令；
- 第四步，把需求说清楚：这是从“能聊”到“能交付”的关键一跃；
- 第五步，立好安全与费用的预期：权限、隐私、钱，先说好再放手。

　　**五步而已。今天走完前三步，这周就能交出第一单。**

## 第一步：想清楚要它干嘛

　　很多人的第一反应是打开应用商店搜“Agent”，然后被一排同名产品当场劝退。先别急着挑产品，回答一个更基本的问题：你想让它干嘛？

　　用上一篇的结论，一句话就够：聊天是“你问它答”，每一步都由你发起；Agent 是“下一步由它自己决定”——你给目标，它自己拆任务、调工具、看结果、接着干，直到交付。这个区别直接决定你的入手路径。对新手来说，可以按任务在哪里执行来分：一类主要在云端处理你上传或连接的资料；另一类获得授权后，直接处理本地文件。界面和它在哪儿干活是两条轴，别混在一起看。

- **云端处理上传或连接的资料**：ChatGPT 的 Agent 模式、Claude 网页版的多步任务，以及 DeepSeek、Kimi、豆包、元宝这些国内产品的网页端——各家能做到哪一步深浅不一，纯对话则早就都有。零安装，注册就能用，免费档大多够练手。拿 Agent 模式来说，官方的描述是给了模型一台“虚拟电脑”，它能自主浏览、替你操作——但够不着你眼前这台电脑：文件要你亲手传，结果要你亲手搬。
- **授权后处理本地文件**：Claude Code、Codex、Qwen Code、Kimi Code 这类跑在终端里的工具，它们能直接读写你电脑上的文件、执行命令、跑测试。走这条路的既有终端工具，也有桌面界面；代价是你得愿意授予它碰本地文件的权限，用终端还得面对一个黑黢黢的窗口。

　　怎么选？我的建议：完全不写代码，先走云端路径，把“说清需求”这门基本功练起来；想让它直接在你的项目里干活，再开终端不迟。举个例子（我的用法）：把上传的一份表格整理成图、把一篇长文拆成摘要，这种几步的小活，云端 Agent 就接得住；要在几十个文件里翻代码、改代码，光靠上传下载就费劲了，该本地 Agent 上场。两条路也不是二选一——我自己就是云端查资料、跑独立小任务，本地改代码，身边用顺手的人，最后基本都落在两个都用。

　　**记住这一句：云端还是本地，区别是它在哪儿干活；喜欢网页、桌面还是终端，是另一层选择。**

## 第二步：选第一站

　　路径定了，才轮到挑产品。别按“哪个最强”来选——第一站的使命是让你把流程跑通，不是一步到位。我的建议是先老老实实回答三个问题：你写代码吗？你在哪儿付费方便？预算多少？

　　然后是三条人群推荐。声明在先：这是我的建议，不是官方结论——

- **不写代码，先免费练手**：DeepSeek、豆包、腾讯元宝的网页或 App，注册就能聊。这个阶段的目标不是选到“最好的”，是赶紧把第四步“说清需求”练起来。
- **写代码，人在大陆，想付费省心**：Kimi Plus（含 Kimi Code）、智谱 GLM Coding、Qwen Code 都能人民币支付；愿意按量付费的，可以买 DeepSeek 的 API，接进支持自定义接口的终端工具里用。
- **有国际支付方式，想用海外主流产品**：ChatGPT Plus 或 Claude Pro，都在每月 $20 左右这一档。

　　**记住这一句：第一站不求最强，求付得起、用得上、留得住——能让你坚持用满一个月的那个，就是对的。**

## 第三步：装起来

　　选了网页路径的朋友，这一节可以整段跳过：注册、登录、开聊，没有安装这回事。走终端路径的，我们拿 Claude Code 走一遍，别家大同小异。macOS 和 Linux 用户跑第一行安装脚本；Windows 用户打开 PowerShell，跑第二行；习惯包管理器的，macOS 走 Homebrew、Windows 走 winget，各取一行：

```bash
# macOS、Linux
curl -fsSL https://claude.ai/install.sh | bash
# Windows（PowerShell）
irm https://claude.ai/install.ps1 | iex
# 或者用包管理器
brew install --cask claude-code
winget install Anthropic.ClaudeCode
```

　　npm 也能装，但官方文档特别叮嘱了两句：需要 Node 22 以上，以及不要用 sudo 装，细节见文末[官方安装文档](https://code.claude.com/docs/en/setup)。装完之后，在你的项目目录里输入 `claude` 启动，第一件事是按提示登录账号。

　　接着你会遇见整个安装流程里最有教育意义的画面：权限询问。默认的手动模式会在需要授权时询问，但不是每改一个文件、每发一次请求都重新问——你此前批准的范围、保存的权限规则和沙箱设置都会影响后续动作，提示里也要读清它批准的是一次动作，还是一类动作。只读不写的，比如读文件本身，通常不用问。别嫌它烦，多看两眼这个动作：第五步要讲的整套安全体系，就建立在这句“先问过你”上。

　　**记住这一句：安装是一次性的，五分钟；权限询问才是第一课——从装上那刻起，就习惯“它在干什么，我先知道”。**

## 第四步：把需求说清楚

　　同一个模型、同一套工具，需求说得清不清楚，结果能差出十万八千里。这不是玄学：Claude Code 的[官方最佳实践](https://code.claude.com/docs/en/best-practices)里白纸黑字写着——“The more precise your instructions, the fewer corrections you'll need”，你的指令越精确，需要的返工就越少。围绕这句话，官方文档里最值得新手带走的做法有四条，我按使用顺序排：

1. **给上下文**：指名具体文件、说清约束条件、给出参考例子。官方原话是 “Reference specific files, mention constraints, and point to example patterns”。记住，Agent 不在你的脑子里，你以为它默认知道的一切，它都不知道。
2. **先计划，后动手**：复杂任务别让它上来就改。官方推荐的工作流是先探索、再计划、你确认、然后动手提交（Explore、Plan、Implement、Commit），还有一条很妙的判断标准——“If you could describe the diff in one sentence, skip the plan”（能用一句话说清这个改动，就跳过计划）。更大的任务，官方甚至建议先让它采访你、把需求整理成一份 SPEC 文档，再开个新会话照着执行。改动落地也有个官方小技巧：先在几个文件上试跑，再放到全部文件上跑。
3. **给它一个能跑的检查**：四条里最值钱的一条。官方原话 “Give Claude a check it can run: tests, a build, a screenshot to compare”——测试、构建、截图对比都行。有了客观的验收标准，Agent 就能自己判断改没改对，你也不用一直当人肉验收机。
4. **小步走，早纠偏**：官方强调 “The best results come from tight feedback loops”（反馈循环收得越紧，结果越好）。方向不对当场说，别攒到最后一起算账；同一个问题纠正超过两次，说明这段上下文已经歪了，官方的建议很干脆：开个新会话重讲。顺手记下另一条官方习惯——不相关的任务之间，清空上下文再开工，上下文越塞越满，模型表现会掉。

　　光说不练假把式，来一组对照示例（我编的，换成你自己的话就行）：

- 差需求：“帮我把这个页面优化一下。”——“优化”是加载速度、视觉效果还是代码质量？它只能猜，猜错全是返工。
- 好需求：“这个页面首屏要 4 秒才出来。先记录页面地址和测试条件，测一下 LCP，找出最主要的加载瓶颈，列出方案让我确认后再改。改完在相同条件下复测，交出前后数据，再跑构建并检查页面功能。”——有现状、有范围、有流程，也有对应目标的验收。
- 差需求：“这个报错帮我修一下。”——它连报错从哪儿来的都还没搞清，只能全网瞎撞。
- 好需求：“跑 `npm test` 报了下面这段错（把报错原文贴给它）。先读相关的代码，把可能的原因列出来给我确认，再动手改，改完重跑一遍测试。”——现状、范围、流程、验收，一样不缺。

　　顺带提醒一句上一组示例里的门道：验收要贴着优化目标写。“首屏快”的验收是同一条件下的 LCP 数据，不是“构建有没有报错”——构建通过只能证明能构建。同理，优化首屏关键图片时得当心：官方明确提醒别对 LCP 图片做懒加载，那会拖慢它自己。

　　**记住这一句：你省掉的每一条信息，它都会用一次返工还给你——把话说清楚，是新手唯一的“高级技巧”。**

## 第五步：立好安全与费用的预期

　　最后一步，也是新手最容易跳过的一步。Agent 和聊天机器人最大的不同，是它真的会动手：动你的文件、跑你的命令、花你的钱。放它出来干活之前，三件事先立好规矩。

　　**先说权限。** 以 Claude Code 为例，官方文档列了六种权限模式，新手记住三种就够：默认的手动模式会在需要授权时询问，但不是每改一个文件、每发一次请求都重新问——此前批准的范围和保存的规则会影响后续操作，第一次见某类工具时会问，之后看你的批准范围；plan 模式只读不改，让它先摸清现状、出方案时最安心；至于 `bypassPermissions`——全部放开、什么都不问——官方文档的警告是 “Only use this mode in isolated environments like containers or VMs”，只应在容器或虚拟机这类隔离环境里用，翻译成人话：日常工作的电脑上，别开。剩下三种模式（自动接受编辑、免常规询问、一律拒绝询问）各有适用场景，等你用出感觉了再研究不迟。想快速看清自己放了多少权限，先用 `/permissions` 查一遍。

　　还有一份“默认要你点头”的清单值得看一眼：在需要逐项批准的手动模式下，所有 shell 命令（ls、cat、grep 这类只读命令除外）、文件修改和联网请求都在授权范围内——注意这是“这类动作”而不是“每一次都重新问一次”。Claude Code 还提供需要主动启用的 shell 沙箱，支持 macOS、Linux 和 WSL2，原生 Windows 暂不支持；它约束的是命令及其子进程，文件工具、MCP 和 hooks 并非全部运行在这套沙箱内，仍需各自的权限控制。官方建议权限搭配沙箱一起用，理由是纵深防御——就算某条恶意指令骗过了模型的判断，沙箱的限制仍然生效。权限和沙箱要配合使用，不能把“装好了”理解成“已经隔离好了”。

　　**再说隐私。** 很多人不知道，消费级 AI 产品的对话可能默认被用来训练模型。[Anthropic 的消费者条款](https://www.anthropic.com/legal/consumer-terms)写得很清楚：你的对话默认可能用于训练其模型，但可以在账号设置里退出；不过点过赞或点过踩的对话、被安全系统标记的对话，即使退出了仍可能用于训练。OpenAI 的公开口径类似：消费版对话默认可用于训练、可在数据控制里关闭，API 的数据默认不用于训练——这一条我没能直接核对原文，均以官方页为准。我的建议只有一句：注册完任何一个 AI 产品，先去设置里把数据相关的开关过一遍；把身份证件、密码密钥、客户数据这些敏感东西喂给它之前，多想三秒。

　　**最后说钱。** 花钱之前分清两套体系：订阅，是固定月费换额度——但刷新周期各不相同，有的按滚动窗口限流，有的还设周额度或月度共享额度，同一产品的不同套餐也可能不同（OpenAI 当前说明 Pro 没有五小时限制；Kimi 网页会员与 Kimi Code 的月度、滚动窗口规则也不一样），购买前看清哪些功能共用额度、何时恢复、超额后是暂停还是另行收费；API，是按 token 计量、用多少付多少，token 可以粗糙理解成模型切文本的最小计费单位。单次任务到底花多少钱？Kimi 官方文档给过一组直观示例：一次简单请求约 0.03 元，一次复杂的多步任务约 1.6 元——这是 Kimi Code 加油包的计费示例，不代表各家 API 的实际费用。DeepSeek 的 API 还有错峰时段半价的机制。按我的粗略估算（非官方数据），轻中度使用 API 一个月也就几元到几十元。我的建议顺序是先用订阅找感觉，等用量稳定、算得清单次成本了，再考虑切到按量的 API。另外提醒一句：订阅不是无限量，ChatGPT 那种 Agent 模式即使订阅了限额也收得很紧——具体数字各家均以官网为准。

　　最后把新手最常见的坑汇总成一张表，每条都标了出处，官方建议和我的建议分开算：

| 常见误区 | 典型现场 | 更好的做法 |
| --- | --- | --- |
| 一次丢超大任务，指望全自动跑完 | “帮我把整个项目重构了，明早来看结果” | 官方指南：自主链越长，错误越会滚雪球；从最简单的方案起步，小步交付 |
| 不复核产出就直接用 | Agent 说“改好了”，看都不看就合并上线 | 官方口径：人工复核仍然关键；让它跑测试或构建，你再过一遍 |
| 把对话窗口当数据库 | 重要约定全靠“我刚才好像说过” | 跨会话的约定写进项目里的说明文件；不相关任务之间清空上下文（官方习惯） |
| 重要环境乱开免询问 | 图省事，把各种确认一口气全关了 | 官方文档警告：免询问模式仅应在容器、虚拟机这类隔离环境使用 |
| 没备份就让它改文件 | 项目还没进 git，改坏了追悔莫及 | 作者建议：先提交、先备份，再放开编辑权限 |
| 以为订阅就是无限量 | 可着劲儿用一整天 | 订阅买的是限时限量的额度：刷新周期各家不同（滚动窗口、周额度或月度共享额度，同一产品不同套餐也可能不同），不是包月包干（各家官方口径，细节以官网为准） |

　　**记住这一句：先立规矩，再放它干活——权限模式、训练开关、费用预期，三件事加起来花不了五分钟。**

## 写在最后

　　路线讲完了，先交一份十分钟能验收的小成果。不写代码的：上传一份脱敏表格，让它按月份汇总金额，交出汇总表和一张图；验收时核对原表总额与汇总总额是否一致，再抽查两个月。写代码的：先备份或提交当前改动，再在练习项目里让它修一个能复现的小问题，交出修改说明和测试结果。两条路都是同一个闭环——给输入、拿成果、自己核对。

　　再往后走（我的建议）：第一周，用云端免费档把“说清需求”练熟，每天让它干一件有明确产出的小事；第二周，装一个终端 Agent，让它读你的代码、回答问题，再让它改一个小函数、自己跑测试。跑通这个闭环，“收藏了等于学会了”这件事，就跟你没关系了。别等“准备好了”再开始——Agent 是用会的，不是学会的。

　　下一篇，工具上手了，该聊模型了：2026 年的秋天，各家模型都卷成了什么样，不同预算分别怎么挑，我们做一次横评。

　　最后照例说句题外话：这篇的调研、大纲和初稿，照旧是我和几个 Agent 一起磨出来的。选题、判断和取舍是我做的，查资料、对口径、摆表格是它们干的——你看，上手之后的样子，大概就是这样。

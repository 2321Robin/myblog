# 上手第一个 Agent：二十分钟，从零到第一份交付

## 一条视频和一个仓库

　　先看一个具体的事实。[B 站有一条视频](https://www.bilibili.com/video/BV1QoaU6gEF2)，标题叫《因为太想卫了于是选择了自己动手，自制网页版可联机卫戍协议》，UP 主一个人把《明日方舟》里的「卫戍协议：盟约」搬进了浏览器，支持单人，也支持 1–4 人联机合作，还能加 AI 队友。视频目前播放量超过九十万，仓库在 GitHub 上有一千七百多 star。

　　我为什么对这件事有发言权：我是[这个项目](https://github.com/sganggs/Stronghold-Protocol)的贡献者之一。我负责定目标、给约束、补充规则并核对结果，Agent 负责把这些要求落成代码。视频里那句「不会弄的话可以让 AI 来」，对项目是真的：112 名干员、283 个技能的规则实现，40 名策略和 23 个盟约的数值核对，一整套插件系统和图形化工作台的搭建，这些活都是这么干的。

　　这就是本篇的立论基础。**在人的持续指导和验收下，Agent 已经能承担这类项目的大量实现工作，而你差的不是能力，是第一次。** 这篇文章不讨论它是什么、能走多远，只做一件事：带你在约二十分钟里，从零走到第一份完整交付。装完、注册完、把话说清楚，剩下的交给它。

## 本文怎么走：一次走完，细节后置

　　下面是一份约二十分钟的练习安排，下载速度、登录和环境检查可能让第一次操作更久；卡住时按文中的检查点处理即可。全文分两半，请按顺序读：

1. **前半，动手篇**：下载安装 → 微信扫码登录 → 新建工作空间 → 选模型 → 写提示词 → 等它干活 → 核对成果。六步都有截图，照着点就行；卡住再回头看后面的展开篇。
2. **后半，展开篇**：第一次跑完之后你一定会冒出的问题——怎么挑工具、怎么把需求说清楚、权限隐私怎么办、钱怎么算。实操中的解释链接会跳到后半篇。

　　三个约定。第一，价格与限免活动天天变，本文信息截至 2026 年 10 月 23 日，动手前请以官方页为准。第二，本文的客户端操作实测于 Windows、WorkBuddy AI 国际版 5.8.4，下载入口图来自国内官网。国内版和国际版界面差不多，但模型列表和活动可能不同：动手前请先确认你能创建执行任务、写入工作目录，并看到可用模型，再继续下面的练习。第三，教学路线固定在 WorkBuddy 上：国内直接访问、微信扫码就能注册，最适合作为第一站。

## 动手篇：从下载到第一份交付

### 第 1 步：下载安装包

　　打开 [WorkBuddy 官网](https://www.workbuddy.cn/)，点「立即下载 WorkBuddy」，悬停展开的菜单里选对应系统的版本：Windows 选 Windows x64（兼容 ARM64），Mac 按芯片选——M 系列选 ARM64，Intel 选 x64。

![WorkBuddy 官网下载页，「立即下载」菜单展开，桌面端列有 Mac、Windows x64、鸿蒙电脑版、Linux，下方移动端列有 iOS、Android、鸿蒙手机版与小程序](/images/posts/agent-getting-started/01-download-page.webp)

　　Windows 下载后双击安装包，按向导完成安装，通常选择「仅为我安装」即可。Mac 打开下载的 .dmg，把 WorkBuddy 拖入 Applications，再从应用程序中启动。我这次安装只花了十几秒。

　　安装时唯一需要注意的是：**不要把项目文件放在安装目录里**，更新或重装时安装目录可能被清空重写。

![WorkBuddy 安装向导的「安装选项」页，选中「仅为我安装」，下方提示已存在一个安装、即将重新安装或升级](/images/posts/agent-getting-started/02-installer.webp)

### 第 2 步：登录，新建工作空间

　　打开 WorkBuddy，微信扫码登录（个人用户选「个人」）——扫码这一下同时完成了注册和登录，没有单独的注册流程。

　　登录后点左侧「新建任务」，屏幕上会弹出工作空间选择框。两种走法选一种就行：点「新建工作空间」，随手起个名字，比如「1」，目录交给客户端管理；或者点「打开本地文件夹」，指向你为这次练习新建的空文件夹——只放练习产物，不要选已有项目或用户主目录。

　　不管选哪种，目的只有一个：让这一单跑在独立的空目录里，别拿已有项目或用户主目录试手。重要文件仍需另行备份。

![WorkBuddy 新建任务界面，工作空间下拉框展开，列出已有空间与「新建工作空间」「打开本地文件夹」「不使用工作空间」三个选项](/images/posts/agent-getting-started/03-new-workspace.webp)

　　还有一处容易漏的开关，不在工作空间下拉框里，而在**输入框正上方**：页面中央「WorkBuddy，我帮你」底下并排两个胶囊按钮——「办公」和「开发」，选中的那个背景更亮（截图里已经是「开发」）。我们这一趟要它写文件、跑命令、起服务器，**切到「开发」模式**就行。

　　先看输入框下沿：左边是工作空间，右边是权限状态；模型入口在输入框右下角。第一次练习保持默认权限：工作空间内的普通操作可能直接执行，遇到越界或高风险动作时会请求确认，不是每改一个文件都重新问。「允许完全访问」会减少确认，它是当前客户端的全局开关，会影响已有任务和之后新建的任务。练习时保持关闭，每次开始任务前都看一眼权限状态——理由放在后面[权限那一节](#权限与隐私先立规矩再放它干活)一起讲。小屏看不清截图时请放大原图查看。

### 第 3 步：选模型，把免费窗口用对

　　输入框右下角是模型选择器，点开，列表里选 **Step 5 Preview**。

![模型选择面板展开，列表中可见均衡、优选、Hy4 preview、Hy3、Step-5-Preview（0.00x，当前勾选）、Deepseek-V4.1-Flash、GPT-6-Astra、GPT-6.1-Sol、GPT-6-Sol 等模型及各自积分倍率](/images/posts/agent-getting-started/04-model-picker.webp)

　　我实操时，这个账号里的 Step 5 Preview 可用，而且标着 0.00x。活动是否仍有效、你的版本和账号能否使用，请看模型选择器里的实际标记。若不再限免，可以使用当前可用的免费模型或体验额度继续练习；出现付费提示先停下来确认，不必为了完成这份待办清单立即订阅。

　　顺带说一句版本：WorkBuddy 分国内版和国际版，界面看着差不多，模型列表和活动可能不同。为什么我用国际版？说来有点好笑，WorkBuddy 在这件事上非常神秘：装了国内版，国际版就用不了，反过来也一样，一台机器上只留得下一个。我本来用的国内版，后来发现国际版多了个免费的 DeepSeek，换过去之后就懒得再折腾回来了。前面第 1 步那张安装截图就是佐证——装国内版时它提示「已存在一个安装」，点下去就是把国际版覆盖掉；反过来装国际版，提示的也是一样的话。这只是我这一台 Windows 电脑上的经历，别当成所有环境的普遍限制。

### 第 4 步：写提示词

　　输入框里写什么，直接决定你拿到什么。第一次的目标不是做多大的东西，而是**跑通「给需求 → 拿成果 → 自己核对」这个闭环**——所以需求里要有明确的产出物，和能一条条对照的验收点。照抄下面这份（[为什么这么写](#把需求说清楚从能聊到能交付)）：

```text
只在当前工作空间创建本次应用和必要的验证文件，不修改已有文件、上级目录或全局配置，不安装额外依赖。先检查已有验证环境；如果缺少工具，先报告缺什么以及替代办法，等我确认后继续。

在当前工作空间里搭一个「待办清单」网页应用，要有真实的功能和像样的界面：
- 单文件 HTML，双击就能在浏览器打开，不依赖任何构建工具；
- 功能：添加待办、勾选完成、删除、按「全部／未完成／已完成」筛选，数据存 localStorage，刷新不丢；
- 每项待办带创建时间，底部显示未完成数量和一键清除已完成；
- 界面用中文，浅色背景，排版和间距讲究一点，参考 Linear 的简洁风格；
- 写完后用 Node 起一个本地服务器验证页面能正常打开，逐条自查上面四点，把自查结果告诉我。
```

　　验收点写具体，是为了让你核对时不含糊——它报「已完成」不算数，你自己点一遍才算。这两段是操作约束，不能代替客户端权限控制；如果环境里没有 Node，让它先报告缺什么、给替代办法，别一路同意安装。

　　后面的截图保留了我最初那次实操。遇到安装依赖误改目录的问题后，我才给上面的提示词补上操作边界；你练习时按这里修订后的要求来，不必照着截图打开完全访问或安装依赖。

### 第 5 步：等它干活

　　点发送，剩下的就交给它了。你会看到对话区一段段展开它的动作——先列计划，再读文件、确认环境、写文件、起服务器验证，中间还夹着几段「深度思考」。**不用一直盯着**，可以去干别的事，隔几分钟回来扫一眼走到哪一步就行：新手看不懂那些工具调用，也没必要看懂，知道它还在推进就够了。

　　顺便说句公道话：WorkBuddy 的过程展示偏克制。工具调用被折叠成一行摘要（「已读取 xxx」「运行」），不像那些终端 Agent 把每条命令原文都摊开；想看清细节得自己点开，跑长了更像一份进度报告。这一点它确实不如同类。

![WorkBuddy 任务执行界面：左侧是工作空间与任务列表，右侧对话区先列计划、读取文件、确认 Node 环境，再写入 HTML 并启动本地服务器验证，下方并行显示三个后台任务，其中一个标记为失败](/images/posts/agent-getting-started/05-task-running.webp)

　　需要你点头时，先看清它准备操作哪个目录、是否安装依赖、是否改动已有文件。确认操作范围和用途都与这次练习相符后再同意；不确定就先取消，让它解释后再继续。这次实操就出了一个小插曲：Agent 报告，安装测试依赖时误动了用户主目录，并留下需要收尾的文件。页面做出来了，过程仍要复核——这也是第一次练习应该使用独立目录、保持默认权限的原因。

### 第 6 步：拿到成果，自己核对

　　跑完之后，在产物卡片或右侧预览中打开页面；没有自动打开，就找到交付的 HTML 文件，按前面约定的方式打开。然后自己逐条点一遍：

　　先添加甲、乙、丙三条待办，核对创建时间；把甲标成完成，检查未完成数和三个筛选项；删除仍未完成的乙，检查计数；刷新同一个页面，确认甲仍已完成、丙仍未完成；最后清除已完成项，确认只移除了甲，丙还在。

　　如果承诺双击使用，就再双击交付文件检查一次，并记下测试所用浏览器；在预览、本地网址和文件之间切换时，原先的本地存储数据不一定共享。

　　对上了，这就是你的第一份 Agent 成果。对不上，把差在哪一条原话告诉它，让它改。

![WorkBuddy 的交付说明：左边逐条对照五点需求、贴出本地服务器验证结果，并报告安装 jsdom 时误改用户主目录及残留文件；右边是待办清单页面预览，条目已勾选完成，底部显示「共 4 项 · 2 项未完成」与「清除已完成」](/images/posts/agent-getting-started/06-result.webp)

　　**第一次的标准不是成果多漂亮，是闭环跑通了。** 接下来，把你自己真正想做的那件事丢给它——深度研究、数据分析、文档和 PPT 生成。模型和额度的事，见后面[钱怎么算](#钱怎么算订阅积分与-api)一节。

## 展开篇：跑通之后，你该知道的几件事

### 第一站为什么选 WorkBuddy

　　不是因为它最强或最好用，是因为它把「上手」路上的坑都填平了：国内直接访问，不用国际支付方式；微信扫码同时完成注册和登录；桌面客户端双击就能装，不需要命令行；一个模型选择器里摆着多家模型，切来切去不用重装工具。

　　那免费能用多久？WorkBuddy 用积分衡量资源消耗，订阅套餐按周期提供积分。新用户注册有赠送积分可领（领不领、领多少以客户端内显示为准）。实际消耗与所选模型和任务处理量有关，不能只看任务名称——模型选择器里各家倍率不同，余额、倍率和明细以客户端为准。

　　顺带一个可选说明：Step 5 Preview 是阶跃星辰的基座模型，稀疏 MoE 架构，总参数 6000 亿、每个 token 激活约 270 亿，1M 上下文（规格见[阶跃官方页面](https://www.stepfun.com/step-5-preview/)）。这些参数不影响这次练习怎么操作，知道它是个能干活的大模型就够了。

　　窗口关了也没事，换一家就是。这一轮抢人的几乎全在编程方向：Trae 国内版的免费档每月 500 积分、功能全开（官方定价页口径），CodeGeeX 有免费模型可用的插件。这些工具各自的脾气、额度怎么算、什么时候该换，留给后面的文章细说——这一篇你只要记住：**WorkBuddy 的窗口只是第一站，不是唯一一站。**

　　想换成别的工具？先分清任务在哪里运行：云端任务通常处理你上传或连接的资料，本地任务则在授权范围内操作你的电脑。本地工具既有 WorkBuddy 这样的桌面界面，也有 IDE 插件和终端入口；同一品牌也可能同时提供本地与云端方式。先看它在哪里干活、获准碰哪些文件，再选自己用得顺手的界面。具体选型和价格，后面的文章再聊。

### 把需求说清楚：从「能聊」到「能交付」

　　同一个模型，需求说得清不清楚，结果能差出十万八千里。四条最值得先带走的做法，按使用顺序排：

1. **给上下文**：指名具体文件、说清约束条件、给出参考例子。Agent 不在你脑子里，你以为它默认知道的一切，它都不知道。
2. **先计划，后动手**：复杂任务别让它上来就改。让它先出执行计划，逐条看每一步贴不贴你的实际情况，确认了再放行。
3. **给它一个能跑的检查**：测试、构建、能逐条对照的验收清单都行。有了客观标准，它才能自己判断改没改对，你也不用当人肉验收机。
4. **小步走，早纠偏**：方向不对当场说，别攒到最后一起算账。同一个问题纠正超过两次，这段上下文基本已经歪了，开个新会话重讲。

　　对照一下差别。差需求：「帮我把这个页面优化一下」——优化是加载速度、视觉效果还是代码质量？它只能猜。好需求：「这个页面首屏要 4 秒才出来。先记录页面地址和测试条件，测一下 LCP，找出最主要的加载瓶颈，列出方案让我确认后再改。改完在相同条件下复测，交出前后数据，再跑构建并检查页面功能。」——有现状、有范围、有流程，有贴着目标的验收。

　　**你省掉的每一条信息，它都会用一次返工还给你。**

### 权限与隐私：先立规矩，再放它干活

　　Agent 真的会动手——动你的文件、跑你的命令。第 2 步说过输入框底部的权限状态：默认权限下，工作空间内的普通操作可能直接执行，越界或高风险动作会请求确认，不是每改一个文件都重新问。「允许完全访问」是全局开关，不只影响眼前这一单；打开后，其他任务也可能直接执行原本需要确认的操作。原则只有一条：**日常电脑上，别开。** 多确认几次不麻烦，被静默改掉一个文件才麻烦。

　　目录收窄任务范围，但不是任何权限状态下都突破不了的硬隔离。第一次用就养成习惯：给它一个专门的空目录，重要文件先备份或先提交 git，再放开编辑权限。真出问题，客户端「帮助 → 诊断工具」和日志目录能帮你定位。

　　隐私是另一件注册当天就该做的事。消费级 AI 产品的对话可能默认被用于训练模型，设置里通常能找到数据相关的开关——注册完任何一个 AI 产品，先把设置过一遍。身份证件、密码密钥、客户数据，喂之前多想三秒。这条没有放之四海通用的口径，各家规则都会变，以你注册时看到的隐私政策为准。

### 钱怎么算：订阅、积分与 API

　　花钱之前先分清两件事：订阅和积分不是两套独立的入口，同一产品的订阅往往按周期发放积分；API 则是另一种接入与计费方式，按对应平台的用量规则结算。

- **订阅**：固定周期付费，通常换取一定额度。注意刷新周期各家不同——有的按滚动窗口限流，有的设周额度或月度共享额度，同一产品不同套餐也可能不一样。订阅不是无限量。
- **积分（Credits）**：WorkBuddy 的计量方式，实际消耗与所选模型和任务处理量有关，模型倍率各有高低，不能按任务叫「问答」还是「文案」推断。余额和明细在「设置 → 积分」看。加赠积分往往有有效期（常见为到账起一个月），大任务排在有效期内前段更划算。
- **API 按量**：按 token 计费，用多少付多少。适合用量稳定、能算清单次成本之后。

　　建议顺序：先用免费档和赠送积分找感觉，等用量稳定、算得清成本了，再决定要不要订阅或切 API。

### 新手最常见的坑

| 常见误区 | 典型现场 | 更好的做法 |
| --- | --- | --- |
| 一次丢超大任务 | 「帮我把整个项目重构了，明早来看结果」 | 从最简单的方案起步，小步交付，自主链越长错误越会滚雪球 |
| 不复核产出就用 | Agent 说「改好了」，看都不看就合并 | 让它跑测试或构建，你再过一遍；对照验收清单逐条核 |
| 把对话窗口当数据库 | 重要约定全靠「我刚才好像说过」 | 跨会话的约定写进项目里的说明文件；不相关任务之间清空上下文 |
| 重要环境乱开免询问 | 图省事，把各种确认一口气全关了 | 免询问仅应在容器、虚拟机这类隔离环境用；日常电脑上别开 |
| 没备份就让它改文件 | 项目还没进 git，改坏了追悔莫及 | 先提交、先备份，再放开编辑权限 |
| 以为订阅就是无限量 | 可着劲儿用一整天 | 订阅买的是限时限量的额度：刷新周期各家不同，购买前看清 |

## 写在最后

　　回到开头那个仓库。我负责定目标、给约束、补充规则并核对结果，Agent 负责把这些要求落成代码——这套分工，你今天已经完整走过一遍了：**你负责说清楚要什么，它负责做出来，你负责核对。**

　　接下来一周，每天找一件有明确产出的小事——整理一份会议纪要、把一张表格做成图、给一段代码补上测试——练习「说清楚、拿结果、自己核对」。等这套流程顺手了，再挑一件真正想做的事拆成几步完成。比如在 QQ 群里接一个 AI 机器人，社区里 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 这类项目已经把通道、人设和插件都备齐了，但每一步都可以让 Agent 带着你做。

　　别等「准备好了」再开始——Agent 是用会的，不是学会的。

　　下一篇，工具上手了，该聊模型了：2026 年的秋天，各家模型都卷成了什么样，不同预算分别怎么挑。

　　最后照例说句题外话：这篇的调研、大纲和初稿，照旧是我和几个 Agent 一起磨出来的。选题、判断和取舍是我做的，查资料、对口径、摆表格是它们干的；至于截图和实际操作过程，那都是我亲手跑出来的——你看，上手之后的样子，大概就是这样。
